# P1-5 扫描件 Demo：多模态补足离线 OCR 短板

日期：2026-10-31。目的：验证 README 已知限制①（扫描版 PDF 无文本层）可以由
**本地多模态模型**补足，且产物直接进产品现有的 `chapter_split.py` 管线——不引入新链路。

## 流程

```
扫描页图片（page_*.png，设备B 手册 PDF 渲染 150dpi，模拟"无文本层的扫描件"）
    → qwen2.5vl:3b（Ollama，本地离线）逐页转录为 Markdown（#/##/### 标注层级）
    → 拼接 → chapter_split.split_into_chapters()（产品代码，零修改）
```

## 文件

| 文件 | 说明 |
|---|---|
| `page_toc.png` / `page_rc.png` / `page_rth.png` | 输入页图（设备B 手册目录页/遥控器页/返航页，150dpi 渲染） |
| `page_*.transcribed.md` | qwen2.5vl:3b 的转录输出 |
| `scan_demo_result.json` | 章节切分结果 + 转录校验 |
| `ocr_demo.py` | 全流程脚本（可重跑） |

## 结果（如实）

- **跑通**：3 页图片 → 转录 → `chapter_split` 解析出 6 个章节（标题层级正确，如 `# 自动返航`、`# 高级智能返航`）。
- **质量不均**：返航页转录完整准确（含正文与表格结构）；**密集排版页欠转录**——遥控器页（实物按键图占半页）只转出 200 字，约为页面实际文字量的 1/4；目录页漏掉"目录"字样。
- **定位**：3B 级本地 VL 模型"能跑通但不够产品化"。更大的本地 VL（7B+）或专用 OCR 可提升密度页覆盖；本 demo 不做产品化，只证明管线可行性。

## 面试口径

README 写"扫描版 PDF 不支持"。现在可以更精确地说：**已验证"扫描页 → 多模态转录 → 现有章节切分"的完整通路在纯离线环境下可行**（模型 2GB、无网、无云 API），当前瓶颈是本地 VL 模型的转录密度，属于可升级项而不是架构缺口。另外实测发现 `ingest.py` 对加密 PDF（AES 空密码）+ 设计型大内容流会直接解析失败（见 `eval/baseline_smoke.md`），这与扫描件问题正交，都需要在"文档接入层"统一处理。
