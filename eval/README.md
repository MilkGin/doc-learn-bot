# eval —— 评测基座

这套评测回答一个问题：**这个 RAG 系统到底行不行，行在哪、不行在哪，能不能量化。**

结论摘要见根目录 [README](../README.md) 的「评测」章节。本文件说明每个文件是什么、怎么复现。

---

## 目录

| 文件 | 作用 |
|---|---|
| `run_eval.py` | 检索指标：`recall@k`（k=1/3/5/10）、`MRR@10`、`hit@5`、正确拒答率与误拒率。确定性，连跑两次逐字节一致 |
| `gen_qa.py` | 评测集生成（四类：单跳 / 多跳 / 难负例 / 无答案），`gold_chunk_ids` 生成后由脚本校验可定位 |
| `embed_cache.py` | 嵌入缓存（`.npz`），避免重复调用嵌入模型；检索评测与端到端共享同一份块向量 |
| `e2e_bge.py` | 端到端答案正确率：同一批题、同一生成器，只换检索配置做对照 |
| `longctx_run.py` | 长上下文 vs RAG：单节 / 双章 / 全篇三档，测正确率、延迟、prompt token |
| `ocr_demo.py` | 扫描页 → 结构化 Markdown（多模态转录）→ 交给章节切分，验证"无文本层 PDF"这条路是否走得通 |

## 结果文件

| 文件 | 内容 |
|---|---|
| `metrics_nomic.json` / `metrics_bge.json` / `metrics_nomic_prefix.json` | 三组嵌入配置的检索指标全量结果（含分语料拆分） |
| `baseline_metrics.json` | 基线（未改动代码）的检索指标 |
| `embed_compare.md` | 嵌入模型对比：总体、分语料、跨语言差距、拒答工作点分析 |
| `e2e_bge.md` | 端到端闭环实验：同题对照、分层 50 题、top-k 4→8 |
| `longctx_vs_rag.md` | 长上下文路线三档对比 + 有效上下文上限实测 |
| `scan_demo/` | 扫描件转录 demo 的输入/输出与结果判定 |

## 指标口径

- **recall@k**：gold 块是否出现在前 k 个检索结果中，分母仅含 **answerable** 题（无答案题不计入）
- **hit@5**：前 5 条里至少命中 1 个 gold 块的题目比例
- **MRR@10**：首个 gold 块排名的倒数均值
- **正确拒答率 / 误拒率**：对无答案题按 top-1 相似度阈值判定，两个方向同时给出（只看拒答率不看误拒率等于自欺）

## 复现

```bash
# 1. 准备语料到 eval/corpus/
# 2. 建索引（不动用户默认索引目录）
DOCS_DIR=./eval/corpus CHROMA_DIR=./eval/chroma python ingest.py
# 3. 检索指标
python eval/run_eval.py
```

> **语料未随仓库发布。** 评测所用三份文档包含第三方版权内容与企业内部资料，不适合公开，
> 因此脚本中的语料标识为脱敏占位名（`kb_demo.md` / `manual_zh.txt` / `paper_en.md`）。
> 想复现的话，自备任意技术文档后按 `gen_qa.py` 的格式重建评测集即可，指标口径完全一致。

## 已知的方法论局限

1. **端到端样本只有 41 题**（分层抽样），正确率绝对值的 95% 置信区间约 ±14pt。前后对照（同题、零新增错误）方向可信，绝对值不可当精确数字引用。
2. **判卷与出题同源**（同一模型、不同 prompt），存在偏差。已通过"生成器与判卷不同源"部分缓解，但未做双判一致性检验。
3. 单次实验，未做多 seed 方差分析。检索侧指标（198 题）统计上稳定，端到端（41 题）不稳定。
